## דרישות טכנולוגיות
- קומפיילר: **LuaLaTeX** (MiKTeX)
- תבנית: קובץ **`.cls`** מותאם
- מבנה תיקייה: `main.tex`, קובץ `.tex` לכל פרק, קובץ `.cls`, `PRD.md`, `PLAN.md`, `TODO.md`, `README.md`

## אופן העבודה (8 שלבים)
1. תיקייה ייעודית · 2. `PRD.md` · 3. `PLAN.md` · 4. `TODO.md` · 5. QA Skills (בעיקר qa-super, qa-BiDi, qa-table, qa-code, qa-img) · 6. הנחיות מדויקות לסוכן · 7. הרצה, בדיקה ותיקון **דרך עדכון סקיל או CLS, לא בתיקון ידני** · 8. שמירת כל קובצי העבודה

**חוק ברזל: רפרודוסיביליות.** לעולם לא מתקנים בעיה ישירות בטקסט. כל תיקון עובר דרך עדכון ה-Skill או ה-CLS.

## Skills חובה
| Skill | תפקיד |
|-------|-------|
| qa-super | אורקסטרטור-על שמנהל את כל משפחת ה-QA |
| qa-BiDi | בדיקת תקינות RTL/LTR בטקסט דו-כיווני |
| qa-table | יישור טבלאות, סדר עמודות |
| qa-code | רקע של pythonbox וגלישת קוד |
| qa-img | מיקום, מסגרות וכיתובים של תמונות |
| qa-typeset | אזהרות הידור (hbox/vbox) |
| qa-infra | מבנה פרויקט תקין |
| qa-cls-version | גרסת ה-CLS מול הגרסה התקנית |

## מהודעת המרצה
- **ועדת מומחים** שמגדירה קריטריונים, ומסמך הוועדה הוא ה-PRD
- סוכנים בתפקידים שונים, **בנויים כ-Skills**
- **Detector** (מגלה) ו-**Fixer** (מתקן), וביקורת "**צוות אדום**" אוטומטית
- **חקר אירוע** על כל תקלה: למה קרתה ולמה לא התגלתה
- גרפים בקוד Python; **אין תמונות מהאינטרנט עם זכויות יוצרים** (עדיף TikZ ואיורים מקוד)
- תיקיית פרומפטים **וקובצי ה-Skills** ב-GitHub
- **Repository חדש**, נפרד ממטלה 01
- README עם צילומי מסך: עמודים, איורים וגרפים, **וצוות הסוכנים בפעולה**
- ניהול משאבים: בחירת מודל לפי משימה
